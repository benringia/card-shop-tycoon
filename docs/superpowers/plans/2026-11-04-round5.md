# Round 5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Calm hovers and presses, a card view with "this copy" first, an Assign job picker, a two-pane Boss Ladder,
sharp pack pictures, one soft level-up sound with three sets, louder town music, and the binder tooltip beside its
card.

**Architecture:**
- Hover moves out of `Util/Motion` into `UIKit` (soft glow / lilac edge built from child objects, decided per
  hover by a pure `HoverRules.kind`). The squishy press loses its bounce.
- Each window change stays in its own controller. Logic it needs that can be tested goes into existing pure modules
  (`JobRules`, `BossRules`, `LevelUpRules`) or new ones (`HoverRules`, `ProductPictureRules`).
- Pack pictures become uploaded PNGs captured from the real models.

**Tech Stack:** Roblox Luau (`--!strict`), Rojo, Lune tests (`lune run tests/run`), Roblox Studio MCP, Python/Pillow
for the picture cut-out.

**Spec:** `docs/superpowers/specs/2026-11-04-round5-design.md` (owner approved 2026-11-04)

## Global Constraints

- "dont touch the combat UI's": the fight HUD, the victory and defeat screens and the combat buttons. The
  non-squishy `Motion.press` path stays as it is.
- No size or position animation on hover; hover changes colour, transparency, glow and stroke only.
- Hover never writes a controller-owned property: a button's `BackgroundColor3`, `TextColor3`, or a row's own
  `UIStroke`. Hover effects live in their own child objects.
- Tap targets are at least 48 px. Check every changed screen in the landscape phone emulator.
- UI text is ASCII plus `·` and emoji. Use the `Star` and `Next` icons, never glyphs.
- Numbers go in `src/shared/Config`. Pure modules take config as arguments and never require siblings.
- Configs a test reads stay plain data (no Color3 or Vector3).
- Sounds are Roblox-licensed only (ProSoundEffects / APMOfficial).
- Studio MCP: reading is fine. Ask before changing the place itself. Scripts live only in the repo.
- Don't touch the owner's open Blender scene unsaved.
- Before Play, check that the Studio script `#Source` matches the repo (Rojo synced).
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit on `hud-creature-pals` only; no
  merge, no push.
- Every task updates DESIGN.md for what it changes. New spec files go in `tests/run.luau` and in CLAUDE.md's test
  list.

## Review Focus

1. **A controller recolours a button while the mouse is on it.** Examples: `setReady` flips Add to party to Locked,
   or the Condenser re-renders. After the mouse leaves, the button shows the controller's latest colour, and no
   sheen or glow is left lit. Owner: Task 1, Studio step.
2. **Rows rebuilt under the mouse** (the Condenser, the card view and the Boss Ladder rebuild rows on click). The new
   rows start unlit, and nothing errors when a hovered row is destroyed mid-tween. Owner: Task 1, Studio step.
3. **The lilac edge in a scrolling list.** It must not be clipped into a hard line at the list edges, and a chosen
   row's gold ring stays visible under the mouse. Owner: Task 1, Studio step on Condenser, card view and Boss
   Ladder.
4. **The Boss Ladder before the server's boss states arrive** (`states[bossId]` nil), and on a phone. It renders
   without errors, and no info goes missing once the states land. Owner: Task 5, Studio step.
5. **A pack look with no picture**, and a picture still processing after upload. The look falls back to the drawn
   icon, and the loading screen never waits forever on a picture. Owner: Task 6, the `ProductPictureRules` test and a
   Studio step.

- [ ] **Step 5: Rebuild the hover in UIKit and calm the press**
  - **`noGreyHover(button, soft: boolean)`** keeps the AutoButtonColor guard. On `MouseEnter` (mouse only, not while
    the button pops out), it computes `HoverRules.kind(soft, button.BackgroundTransparency, isLocked(button))`.
    - `isLocked(button)` is true when its `BackgroundColor3` equals `UIKit.Colors.Locked` or
      `UIKit.softFill(UIKit.Colors.Locked)`.
  - **`"glow"`:**
    - Tween the button's existing `Glow` image's `ImageTransparency` to `HOVER.glowTransparency`. Its rest value is
      saved once as a `RestTransparency` attribute.
    - Tween a `UIScale` named `HoverGrow` on the Glow to `HOVER.glowScale`.
    - Fade a child Frame `HoverSheen` to `HOVER.sheen`. It is white, full size, `ZIndex` 0, with the button's
      UICorner radius.
  - **`"edge"`:**
    - Fade in a lilac copy of the soft glow: `UIKit.glow(button, Color3.fromRGB(table.unpack(HOVER.edge)),
      cornerRadius, 0, 1)`, renamed at once from `Glow` to `HoverEdge` (so `softButton`'s Glow refit and the glow
      kind never pick it up). It tweens to `HOVER.edgeGlow`, and its cut-out centre never covers the row or its
      ring.
    - Fade in a child Frame `HoverTint` to `HOVER.tint`. It is lilac, inset by `HOVER.tintInset` px, `ZIndex` 0,
      with the corner radius.
  - **Leaving:** `MouseLeave` tweens everything back, using `HOVER_SECONDS` for in and `HOVER_OUT_SECONDS` for out
    (Quad or Sine, eased Out, never Back).
  - **`"none"`** does nothing.
  - **Who calls it:** `softButton` calls `noGreyHover(button, true)`. `creamWindow`'s `soften` calls
    `noGreyHover(child, false)` and skips buttons already marked `SoftHover`.
  - **`Motion.press(button, squishy)`:** when `squishy`, press to `SQUISH_PRESS` over `PRESS_SECONDS` (Quad Out) and
    release to 1 over `SQUISH_RELEASE_SECONDS` (Quad Out). The non-squishy branch is unchanged. Release always goes
    to 1, since nothing hovers at another size.
  - **Delete the old hovers:** remove `Motion.hover` and its tables. Remove the hover block in `CardBuyController`,
    and `addHover` plus its calls in `ShowcaseController`.
