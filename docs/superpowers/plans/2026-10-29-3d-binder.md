# 3D Binder (Collector's Desk) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat 2D binder book with a real 3D ring binder lying open on a desk: 3 x 3 sleeved pockets, bending page turns, divider tabs, cards that lift out of their sleeve.

**Architecture:** The scene is client-only parts on a stage far above the world (like the card view). A Scriptable camera frames the binder inside the screen rectangle that today's 2D layout already computes. Card faces are today's `CardFace` UI on SurfaceGuis (one canvas per page). Input goes through camera raycasts, not GUI buttons. A turning page is a pre-built chain of strips showing light versions of the cards. Pure maths (curl, gestures, camera fit, pocket hit-testing) lives in Roblox-free modules with Lune tests. `BinderController` keeps data, filters, tooltips, the Bag and the 2D overlay, and drives the new `Util/BinderDesk` (scene, camera, picking) and `Util/PageTurner` (the turning leaf).

**Tech Stack:** Roblox Luau (`--!strict`), Rojo, Lune tests (`lune run tests/run`), Roblox Studio MCP for Play checks.

**Spec:** `docs/superpowers/specs/2026-10-29-3d-binder-design.md`

## Global Constraints

- Client-only: no server, remote or saved-data changes.
- 3 x 3 pockets per page on every screen, 18 cards a spread; no phone fallback to bigger pockets.
- The lamp light pool and the sleeve glints are painted (gradients, overlays) and look the same at every graphics quality level; a real light may only add on top.
- Nothing of the game world may show behind or through the scene.
- Tunable numbers go in `src/shared/Config/BinderDesk.luau` (new) or `Config/Collection`, never inline.
- Pure logic goes in Roblox-free modules under `src/shared/Util` with Lune tests in `tests/`, registered in `tests/run.luau` and listed in CLAUDE.md's test list.
- `--!strict` on every file; UI text is plain ASCII plus `·` and emoji only; tap targets at least 48 px (`UIStyle.MIN_TAP`).
- Code lives in the repo only; in Studio, Play-testing and reading are fine, editing the place is not.
- DESIGN.md (binder part of 10.6, file tree, section 13) is updated in the same commit as the code it describes.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Verification for Roblox-side tasks is a Studio Play check through the MCP (`start_stop_play`, `execute_luau` in the Client data model, `screen_capture`). Mouse input uses GUI coordinates (capture y minus the 58 px inset). Buttons are pressed by setting `GuiService.SelectedObject` and pressing Return.

## Review Focus

1. Card view round trip: binder, then a card, then closing the card view must put the camera back on the binder stage with the binder's field of view and the same spread. The inspector saves and restores the camera on its own, and the binder's Scriptable camera sits under that (Task 6 Studio check).
2. Every way of closing restores the camera type, CFrame, field of view and audio listener: B, the close button, opening another main window, a fight starting, the character respawning (Task 4 and Task 7 Studio checks).
3. The collection changing mid-turn (a pack opened, a card put on display) redraws once the page lands, with no card lost or shown twice (Task 5 Studio check).
4. A filter that matches nothing (search "zzz") gives empty pages and "0 / 0", and turning or clicking does nothing harmful (Task 2 Lune test and Task 4 Studio check).
5. Holding E past the last spread, pressing Q mid forward turn, or dragging while a key turn runs never turns past the ends and never gets stuck (Task 1 Lune tests and Task 5 Studio check).

- Produces (pure):
  - `export type Layout = { columns: number, rows: number, padX: number, padY: number, gap: number }`
  - `export type Box = { u0: number, v0: number, u1: number, v1: number }`: page fractions with u from the page's left and v from its top.
  - `BinderFit.pocketBox(index: number, layout: Layout): Box`: index 1-9, left to right then top to bottom.
  - `BinderFit.pocketAt(u: number, v: number, layout: Layout): number?`: nil in margins and gaps or outside 0-1.
  - `BinderFit.distance(book: { w: number, h: number }, rect: { w: number, h: number }, view: { w: number, h: number }, fovY: number, tilt: number): number`: camera distance (studs) at which the book, tilted by `tilt` degrees (effective height `h * cos(tilt)`), fits inside `rect` pixels of a `view`-pixel screen.
  - `BinderFit.shift(rect: { x: number, y: number, w: number, h: number }, view: { w: number, h: number }, distance: number, fovY: number): (number, number)`: the book centre's offset (studs, along the camera's right and up) that puts it at the rect's centre; up is positive.

- [ ] **Step 3: Implement** `BinderFit`. Pocket width is `(1 - 2*padX - (columns-1)*gap) / columns`, and height likewise with padY and rows. `distance` takes the larger of the width-bound `w * view.w / (2 * tan(fovX/2) * rect.w)` (with `tan(fovX/2) = tan(fovY/2) * view.w / view.h`) and the height-bound `h*cos(tilt) * view.h / (2 * tan(fovY/2) * rect.h)`. `shift` uses studs-per-pixel `k = 2 * distance * tan(fovY/2) / view.h`.
