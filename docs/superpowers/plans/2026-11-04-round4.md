# Round 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Round 4 polishes what players meet first and makes shop levels rewarding:
- shop levels 1-100 with rewards and a light-pillar level-up effect;
- creature-free binder covers and a smoother card hover;
- the tidy Condenser and Order Stock windows;
- new summon sounds;
- a loading screen that waits for every first picture;
- portrait levels that count up.

**Architecture:**
- **Pure rules** live in Roblox-free `src/shared/Util` modules with Lune tests: `LevelMath`, `LevelUpRules`, `OrderRules`, `LoadingRules`, `CondenseRules`, `ItemRules`. **Plain-data configs** hold every tested number.
- **One new server service** (`LevelUpService`) owns:
  - the level-up broadcast, including holding it while the player fights;
  - the pack reward;
  - opening Bag packs.
  
  `EconomyService` keeps owning cash, XP and levels. `CardService.AddXP` stays the only place creature levels change.
- **One new client controller** (`LevelUpController`) plays the effect, which is built by `Util/LevelUpFx` from Blender-rendered textures.

**Tech Stack:** Roblox / Luau (`--!strict`), Rojo, Lune tests (`lune run tests/run`), Blender via the Blender MCP,
Roblox Studio MCP.

**Spec:** `docs/superpowers/specs/2026-11-04-round4-design.md` (owner approved 2026-11-04). Read it with this plan. Its
mockups are in `.superpowers/brainstorm/13775-1793692558/content/` (`round4.html`, `round4c.html`).

## Global Constraints

The spec's Constraints section and CLAUDE.md's rules apply to every task.

**Server and data**
- Server authoritative. Cash and XP change only through EconomyService. Packs roll only on the server.
- Every remote is in `src/shared/Remotes.luau`. Validate argument types, ownership and state, and rate-limit with
  `src/server/Util/RateLimiter.luau`.
- Saved state goes through `DataService.Register`. No saved-shape change this round: the level is derived from XP;
  the new Bag item is a new id in the existing items map.

**Config and tests**
- Tunable numbers live in `src/shared/Config`. Numbers a test reads go in plain-data configs (no Color3, Vector3 or
  requires).
- Pure modules don't require siblings; callers pass the config in.
- New specs are registered in `tests/run.luau`.
- After adding files, run `rojo sourcemap default.project.json -o sourcemap.json`.
- Before Play, check that Rojo synced: compare the local file's byte length with Studio's `#Source`.

**UI**
- Cotton candy windows (`UIKit.panel`, `UIKit.colorsFor`, soft buttons, `Config/CreamTheme`, `Config/BabyColors`).
- Taps are at least 48 px.
- Text is plain ASCII plus `·` and emoji. ★ and → draw as boxes; use the `Config/UIIcons` `Star` / `Next` icons.
- Don't touch the combat UI (fight HUD, victory and defeat screens, combat buttons).

**Assets**
- Sounds: Roblox-licensed only (ProSoundEffects / APMOfficial). Find them with Studio MCP `search_asset`.
- Images: upload by serving the folder locally (`python -m http.server 8765` in that folder), then call Studio MCP
  `upload_image` with `http://127.0.0.1:8765/<file>`. Uploads are capped at 1024 px.
- Blender: before saving a `.blend`, delete raw `*_Src` objects and purge orphans. Before committing it, check that
  the scene's `blendermcp_*key*` / `*secret*` fields are empty (print lengths only).

**Studio and git**
- Studio MCP: reading is fine; ask before changing the place itself.
- Keep each file's line endings when patching.
- Don't kill the owner's `rojo serve` on port 34872.
- Commit on `hud-creature-pals`; never push or merge.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Docs**
- DESIGN.md changes in the same task as the code. Don't tick boxes: the owner ticks after their Studio check.

## Review Focus

1. **A missing, moderated or failed asset id** (an icon, a pack front, an effect texture). The loading screen must
   treat a failed fetch as settled, not wait the full 30 s on every join. Pinned by Task 9's `LoadingRules.settled`
   test.
2. **XP gained at or past Lv 100.** No level-up, no reward, no effect; the XP pill shows "MAX". Pinned by Task 1's
   cap tests and Task 2's reward-clamp test.
3. **A shop level-up held during a fight when the player leaves, teleports or the fight never ends cleanly.** No
   error, nothing broadcast for a gone player, pending state cleared. Pinned by Task 2's `LevelUpRules.merge` tests;
   the server cleanup is checked by the reviewer.
4. **The Bag's Open button abused.** Spam taps, a count of 0, a non-pack item id, a number instead of a string,
   tapping mid-fight. Each is refused with no roll and no item lost. Pinned by Task 2's `ItemRules.openablePack`
   test.
5. **The effect when the target isn't there.** A character mid-respawn, a creature not streamed in, the other
   player in another place, a worker rig without a visual. Skip silently; never error on nil. Checked in Task 8's
   Studio pass and by the reviewer.

- Produces:
  - `LevelUpRules.rewards(cfg, from: number, to: number): { cash: number, packs: number }`. This sums levels from+1

  - `LevelUpRules.rewardText(cfg, level): string`, e.g. `"+$70"` or `"+$100 · +1 pack"`.
  - `LevelUpRules.merge(pending: { from: number, to: number }?, from: number, to: number): { from: number, to: number }`.
    It keeps the earliest from and the latest to.
  - `ItemRules.openablePack(itemsConfig, itemId: any): string?`. It returns the item's `open` product id, or nil for
    a non-string, unknown or non-openable id.
  - `EconomyService.OnLevelUp(handler: (player: Player, from: number, to: number) -> ())`.
  - `PackService.OpenItemPack(player: Player, productId: string)`: a normal roll with pity and the `packsOpened`
    stat, delivered with `PackOpened`.
  - The remote `OpenBagPack` (client to server: `itemId: string`).
  - `LevelUpService.Start()`. Task 8 adds the broadcast to this service.
