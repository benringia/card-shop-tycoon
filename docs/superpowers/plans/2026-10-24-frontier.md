# Battles Part 3a (The Frontier) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second Roblox place (the Frontier) built from this repo, with high-level monsters that drop Star Shards (the first item in a new inventory) and Frontier-exclusive cards, reached by teleport from a plaza portal (Explore / Join friend) and back.

**Architecture:** One codebase, two places: `frontier.project.json` tags the Frontier's Workspace with `PlaceKind = "Frontier"`; `shared/Util/Place` reads it, and both entry scripts start only that place's services/controllers. The wild code (WildService, BattleService, MonsterController, BattleController) reads its world from `Place.getWorld()` (`Config/Wild` or `Config/Frontier`). Travel uses plain `TeleportService:TeleportAsync`: a teleport is a leave, so the existing leave path ends fights and saves, and ProfileStore hands the session to the next server.

**Tech Stack:** Roblox Luau (`--!strict`), Rojo 7, Lune 0.11 (`lune run tests/run`).

**Spec:** `docs/superpowers/specs/2026-10-24-frontier-design.md`

## Global Constraints

- Server authoritative; cash via EconomyService, XP via CardService.AddXP, cards via CardService.AddFresh (grade rolled on the server), items via ItemService only.
- Every remote in `Remotes.luau`, validated and rate-limited. Destination place ids come from `Config/Places.luau` only.
- Tunables in Config: `Config/Frontier.luau` (same shape as `Config/Wild.luau` plus drop fields), `Config/Items.luau`, `Config/Places.luau` (`MAIN_PLACE_ID`, `FRONTIER_PLACE_ID = 0` until created).
- Drops: Star Shard 3% (1) normal / 10% (1) elite; Frontier card 3% normal / 10% elite; elites 1 in 6.
- Zones: Frostwood 15–25 (Tide, Shade), Stormpeak 25–35 (Volt, Ember), The Rift 35–50 (all five, all chase).
- Frontier cards: 6 (2 Rare, 2 Epic, 2 Legendary), never in packs; Epic/Legendary have signatures.
- Items saved as `items = { [itemId] = count }`, schema v10; counts whole numbers 0–9999 (`MAX_STACK`); unknown ids dropped.
- Condenser: shards only cover the shortfall after real duplicates, at most `floor(cost × MAX_SHARD_SHARE)` with `MAX_SHARD_SHARE = 0.5`.
- UI ≥ 48 px buttons, ASCII plus `·` and emoji.

## Review Focus

1. **A teleport that fails** (Studio, `FRONTIER_PLACE_ID = 0`, Roblox error) → player stays, a message explains, nothing ends or saves early, they can retry.
2. **Join friend with a stale or forged target** (not a friend, friend left the Frontier, friend in the main game) → refused with a message, no teleport.
3. **Frontier place boot with shop data present** (layout, jobs, boxes in the save) → none of it is touched or lost; it comes back on return to the main game.
4. **Condense with shards when the player's shard count changed** (spent elsewhere, 0) → server recounts; never takes more shards than held or more than half the cost.
5. **Code that assumes plots in the Frontier** (any `PlotService.GetPlot` / `PlotId` waiter that still runs) → no errors, no infinite yields that block a controller from starting.
